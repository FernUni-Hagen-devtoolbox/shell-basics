Starten und Stoppen einer Shell

Wir erhalten Zugang zur Shell über ein Terminal. Ein Terminal zu starten ist je nach Betriebssystem unterschiedlich.

Unter Linux müssen Sie lediglich das entsprechende Terminal-Programm finden und starten. Gängige Varianten sind:

  • gnome-terminal
  • xterm
  • konsole

Unter macOS können Sie ebenfalls einfach eine Instanz der Terminal.app starten.

Windows hat eine eigene Shell für das Windows Betriebssystem. Da wir in diesem Kurs aber mit Linux (bzw. unixoiden Systemen, wie macOS) arbeiten, müssen Sie zunächst WSL2 installieren. Sie finden dazu ein eigenes DevToolbox-Modul in der linken Leiste. Dieser Lernpfad setzt noch nicht voraus, dass Sie die Shell auf Ihrem eigenen lokalen System verwenden. Sie können diesen Schritt also auch zunächst überspringen. Im weiteren Verlauf der Bearbeitung wird Ihnen eine Shell über den Browser zur Verfügung gestellt.

Nach dem Starten des Terminals erwartet Sie der Prompt der Shell, auch Befehlszeile genannt. Dieser kann viele Formen annehmen, sieht oft aber folgendermaßen aus:

<benutzer:in>@<rechner>:~$

Für den konkreten Nutzer foo der auf dem System bar arbeitet, wäre der Prompt also:

foo@bar:~$

Hinter dem $-Zeichen können nun Befehle eingegeben werden. Mit der Enter-Taste bestätigen Sie die Eingabe. Sie können die Shell beenden, indem Sie das Terminal-Fenster schließen oder indem Sie folgenden Befehl ausführen:

foo@bar:~$ exit

Alternativ können Sie die Tastenkombination Strg+d drücken. In den praktischen Übungen öffnen Sie bei Bedarf über das Plus-Symbol im JupyterLab Launcher ein neues Terminal.

Aufbau von Befehlen

Shell-Befehle folgen in der Regel dem gleichen Aufbau:

befehl [optionen] [argumente]

Der exit-Befehl aus der vorherigen Eingabe kommt beispielsweise ohne Optionen oder Argumente aus.

Befehlsdokumentation und Hilfesysteme

In der letzten Einheit haben Sie einige neue Befehle kennengelernt. Bei der Arbeit in der Shell werden Ihnen immer wieder Fehlermeldungen oder unbekannte Optionen begegnen. Auch wenn Sie einfach vergessen haben, wie genau diese eine Option für diesen einen speziellen Befehl, den Sie nur einmal im Quartal verwenden, aussah, benötigen Sie Hilfe. Genau für solche Situationen und Fälle bieten viele Programme eine Dokumentation und Hilfe zur Nutzung, die direkt über das Terminal aufgerufen werden kann. Um diese Hilfesysteme geht es in diesem Abschnitt.

Die einfachste Form der Hilfe erreichen Sie durch die Option --help.

foo@bar:~$ cat --help

Je nach Komplexität des Befehls variiert die Länge und der Detailgrad der Ausgabe von --help. In den allermeisten Fällen sind Sie gut beraten zuerst mit --help zu arbeiten und erst wenn so keine Lösung zu finden ist, eine der folgenden Methoden zu verwenden.

Ein weiterer hilfreicher Befehl ist whatis. Damit erhalten Sie eine Kurzbeschreibung zu einem Eintrag aus den installierten Handbuchseiten. Der Befehl analysiert keine beliebigen Skripte. Unbekannte Skripte sollten Sie deshalb lesen und ihre Herkunft prüfen, bevor Sie sie ausführen. In der kommenden Übung werden wir mit diesen ersten beiden Methoden einige komplexe Befehle analysieren.

Sollten Sie je an den Punkt kommen, an dem --help und whatis nicht mehr ausreichen, dann sollten Sie die manpage zu Rate ziehen. Dahinter steckt die ausführliche Dokumentation eines Befehls in einer (mehr oder weniger) standardisierten Form. Der Name Manpage leitet sich vom englischen manual ab, was so viel wie Handbuch bedeutet. Diese Handbücher umfassen oftmals weitaus mehr Informationen als die, die Sie über --help in Erfahrung bringen können. Sie rufen eine manpage folgendermaßen auf:

foo@bar:~$ man <befehl>

Anders als --help ist man ein eigener Befehl. Als Argument erhält er den Namen des Befehls, dessen Manpage angezeigt werden soll. Da Manpages in der Regel relativ groß sind, werden sie normalerweise automatisch mit einem sogenannten Pager angezeigt. Mit den Pfeiltasten bewegen Sie sich im Text. Mit der Taste Q beenden Sie den Pager und kehren zum Terminal zurück.

Rechte, Nutzer:innen, Gruppen und der sudo-Befehl

Alle gängigen Betriebssysteme haben ein Rechtesystem, mit dem der Zugriff auf Dateien und Funktionalitäten verwaltet wird. Unter Unix gibt es standardmäßig immer mindestens einen Nutzer, den root-Nutzer. Daneben können beliebig viele weitere Nutzer:innen angelegt werden. Diese normalen Nutzer:innen haben im Vergleich zum root-Nutzer eingeschränkte Rechte. Beispielsweise haben sie keinen Zugriff auf bestimmte Systemordner und -dateien. Diese Regulierung ist vor allem zum Schutz des Systems vorhanden. Normale Nutzer:innen sollen beispielsweise nicht die Möglichkeit haben, Systemdateien zu verändern oder zu löschen, wodurch die Funktionalität für alle Nutzer:innen beeinflusst würde. Stattdessen besitzen Nutzer:innen ein sogenanntes Home-Verzeichnis als persönlichen Arbeitsbereich. Dort können sie in der Regel eigene Dateien und Verzeichnisse anlegen. Das Home-Verzeichnis befindet sich unter:

/home/<benutzer:in>/

Neben den individuellen Rechten gibt es eine weitere Ebene zur Verwaltung von Zugriffsrechten: die Verwendung von Gruppen. Jede Datei und jedes Verzeichnis gehört daher nicht nur einer Person, sondern ist auch einer Gruppe zugeordnet. Welche Gruppen vorhanden sind und welche Gruppe für neue Dateien verwendet wird, hängt von der Systemkonfiguration ab. Darüber hinaus gibt es Rechte für alle anderen Nutzer:innen. Damit sind Personen gemeint, denen die Datei oder das Verzeichnis nicht gehört und die nicht der zugeordneten Gruppe angehören. Für diese drei Kategorien von Zugriffsrechten gibt es jeweils drei Arten von Rechten: Leserechte, Schreibrechte und Ausführungsrechte.

Es gibt bestimmte Funktionen, die ausschließlich vom root-Nutzer ausgeführt werden können. Dazu zählen bspw. die Verwaltung von Gruppen, die Installation systemweiter Software oder die Verwaltung von Diensten. Um diese Einschränkung für einzelne erlaubte Befehle zu erhalten, kann ein System den sudo-Befehl bereitstellen. Dabei steht sudo für superuser do. Welche Personen welche Befehle damit ausführen dürfen, legt die jeweilige Systemkonfiguration fest. Der sudo-Befehl wird einem entsprechend freigegebenen Befehl vorangestellt.

foo@bar:~$ sudo <befehl>

Ob eine Passworteingabe erforderlich ist und wie lange eine erfolgreiche Authentifizierung gilt, hängt ebenfalls von dieser Konfiguration ab. In der MyBinder-Umgebung dieses Kurses stehen keine administrativen sudo-Aufgaben zur Verfügung.
