Starten und Stoppen einer Shell

Wir erhalten Zugang zur Shell über ein Terminal. Ein Terminal zu starten ist je nach Betriebssystem unterschiedlich.

Unter Linux müssen Sie lediglich das entsprechende Terminal-Programm finden und starten. Gängige Varianten sind:

  • gnome-terminal
  • xterm
  • konsole

Unter macOS können Sie ebenfalls einfach eine Instanz der Terminal.app starten.

Windows hat eine eigene Shell für das Windows Betriebssystem. Da wir in diesem Kurs aber mit Linux (bzw. unixoiden Systemen, wie macOS) arbeiten, müssen Sie zunächst WSL2 installieren. Sie finden dazu ein eigenes DevToolbox-Modul in der linken Leiste. Dieser Lernpfad setzt noch nicht voraus, dass Sie die Shell auf Ihrem eigenen lokalen System verwenden. Sie können diesen Schritt also auch zunächst überspringen. Im weiteren Verlauf der Bearbeitung wird Ihnen eine Shell über den Browser zur Verfügung gestellt.

Nach dem starten des Terminals erwartet sie der Prompt der Shell, auch Befehlszeile genannt. Dieser kann viele Formen annehmen, sieht oft aber folgendermaßen aus:

<benutzer:in>@<rechner>:~$

Für den konkreten Nutzer foo der auf dem System bar arbeiten wäre der Prompt also:

foo@bar:~$

Hinter dem $-Zeichen können nun Befehle eingegeben werden. Mit der Enter-Taste bestätigen sie die Eingabe. Sie können die Shell beenden indem Sie das Terminal-Fenster schließen oder indem Sie folgenden Befehl ausführen:

foo@bar:~$ exit

Alternativ können Sie die Tastenkombination Strg+d drücken.

Aufbau von Befehlen

Shell-Befehle folgen in der Regel dem gleichen Aufbau:

befehl [optionen] [argumente]

Der exit-Befehl aus aus der vorherigen Eingabe kommt beispielsweise ohne Optionen oder Argumente aus.

Befehlsdokumentation und Hilfesysteme

In der letzten Einheit haben Sie einige neue Befehle kennengelernt. Am Ende der letzten Übung sind Sie mit einem Fehler konfrontiert worden. Solche Situationen, in denen Sie Hilfe benötigen, werden Ihnen immer wieder begegnen. Auch wenn Sie einfach vergessen haben, wie genau diese eine Option für diesen einen speziellen Befehl, den Sie nur einmal im Quartal verwenden, aussah, benötigen Sie Hilfe. Genau für solche Situationen und Fälle besitzen die allermeisten Befehle eine Dokumentation und Hilfe zur Nutzung, welche direkt über das Terminal selbst aufgerufen werden kann. Um diese Systeme zur Hilfe geht es in diesem Abschnitt.

Die einfachste Form der Hilfe erreichen Sie durch die Option --help.

foo@bar:~$ cat --help

Je nach Komplexität des Befehls variiert die Länge und der Detailgrad der Ausgabe von --help. In den allermeisten Fällen sind Sie gut beraten zuerst mit --help zu arbeiten und erst wenn so keine Lösung zu finden ist, eine der folgenden Methoden zu verwenden.

Ein weiterer hilfreicher Befehl ist whatis. Damit bekommen Sie zu einem anderen Befehl eine Kurzbeschreibung. Das ist besonders hilfreich, wenn ein unbekannter Befehl oder ein Skript vorliegt. In solchen Fällen sollte man natürlich immer zuerst prüfen, was die einzelnen Befehle tun, bevor man sie blind auf dem System ausführt. In der kommenden Übung werden wir mit diesen ersten beiden Methoden einige komplexe Befehle analysieren.

Sollten Sie je an zu dem Punkt kommen, an dem --help und whatis nicht mehr ausreichen, dann sollten Sie die manpage zu Rate ziehen. Dahinter steckt die ausführliche Dokumentation eines Befehls in einer (mehr oder weniger) standardisierten Form. Der name manpage leitet sich vom englischen manual ab, was so viel wie Handbuch bedeutet. Diese Handbücher umfassen oftmals weitaus mehr Informationen als die, die Sie über --help in Erfahrung bringen können. Sie rufen eine manpage folgendermaßen auf:

foo@bar:~$ man <befehl>

Statt eine Option, wie --help, ist man ein eigener Befehl, der als Argument den Befehl bekommt, für welchen er die manpage anzeigen soll. Da manpages in der Regel relativ groß sind, werden sie normalerweise automatisch mit einem sogenannten pager angezeigt. Im Lernpfad: Fortgeschrittene werden wir uns den pager less näher anschauen. Falls Sie jemals das Gefühl haben, auf einer manpage gefangen zu sein, drücken Sie die Taste Q, damit sollten Sie in den meisten Fällen zum Terminal zurückkehren.

Rechte, Nutzer:innen, Gruppen und der sudo-Befehl

Alle gängigen Betriebssysteme haben ein Rechtesystem, mit dem der Zugriff auf Dateien und Funktionalitäten verwaltet wird. Unter Unix gibt es standardmäßig immer mindestens einen Nutzer, den root-Nutzer. Daneben können beliebig viele weitere Nutzer:innen angelegt werden. Diese normalen Nutzer:innen haben im Vergleich zum root-Nutzer eingeschränkte Rechte. Beispielsweise haben sie keinen Zugriff auf bestimmte Systemordner und -dateien. Diese Regulierung ist vor allem zum Schutz des Systems vorhanden. Eine normale Nutzerin soll bspw. nicht die Möglichkeit haben Systemdateien zu verändern oder zu löschen, wodurch die Funktionalität für alle Nutzer:innen beeinflusst würde. Stattdessen besitzen Nutzer:innen ein sogenanntes home-Verzeichnis, einen eigenen Unterordner im Dateisystem, in dem sie uneingeschränkte Rechte besitzen. Dateien und Ordner, die innerhalb dieses Ordners angelegt werden, gehören dem/der Nutzer:in. Das home-Verzeichnis befindet sich unter:

/home/<benutzer:in>/

Neben den individuellen Rechten gibt es eine weitere Ebene zur Verwaltung von Zugriffsrechten: die Verwendung von Gruppen. Jede Datei und jedes Verzeichnis gehören daher nicht nur einem/einer Nutzer:in, sondern sind auch einer Gruppe zugeordnet. Standardmäßig besitzt jeder/jede Nutzer:in eine eigene Gruppe, die für neu erstellte Dateien und Verzeichnisse verwendet wird und in der er/sie das einzige Mitglied ist. Darüber hinaus gibt es Rechte für alle anderen Nutzer:innen, also für diejenigen, denen die betreffende Datei oder das Verzeichnis weder gehört noch die Teil der zugehörigen Gruppe sind. Für diese drei Kategorien von Zugriffsrechten gibt es jeweils drei Arten von Rechten: Leserechte, Schreibrechte und Ausführungsrechte.

Es gibt gewisse Funktionen die ausschließlich vom root-Nutzer ausgeführt werden können. Dazu zählen bspw. die Verwaltung von Gruppen, die Installation systemweiter Software oder die Verwaltung von Diensten. Um diese Einschränkung temporär zu umgehen, gibt es den sudo-Befehl. Dabei steht sudo für superuser do. Nutzer:innen, die sudo-Rechte besitzen, haben, je nach Konfiguration erweiterte Rechte, in der Regel sogar die gleichen Rechte, wie der root-Nutzer. Der sudo-Befehl wird dem Befehl, der erweiterte Rechte erfordert vorne angestellt.

foo@bar:~$ sudo <befehl>

Wenn Sie den sudo-Befehl zum ersten Mal in einem Terminal verwenden, müssen Sie die Nutzung mit Ihrem Passwort authentifizieren. Danach können sie für eine bestimmte Zeit (~5min) Befehle mit sudo in diesem Terminal ausführen, bevor Sie erneut Ihr Passwort bestätigen müssen.

Die Rechte für den Zugriff über sudo werden in der Datei /etc/sudoers verwaltet. In dieser Datei befindet sich eine Gruppe, oft mit dem Namen sudo oder wheel (von to take the wheel, das Steuer übernehmen), die für die Erweiterung der Rechte von einfachen Nutzer:innen vorgesehen ist. Wenn Sie nun Teil der dieser Gruppe sind, erhalten sie darüber die Möglichkeit den sudo-Befehl zu verwenden.
