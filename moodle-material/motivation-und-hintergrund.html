Warum beschäftigen wir uns mir der Shell?

Wer in der Informatik mit realen Systemen arbeitet, stößt früher oder später auf Umgebungen, die sich nicht anklicken lassen: Server-, Cloud- und Hochleistungsrechner bieten in der Regel keine grafische Oberfläche (GUI) an und können nur über eine Shell genutzt werden. Aber auch auf dem lokalen System ist der sichere Umgang mit der Shell Voraussetzung für die effektive und vor allem effiziente Nutzung vieler moderner IT-Werkzeuge, aber auch für die Erstellung von Entwicklungsumgebungen und die Installation von Software sowie Infrastruktur. Den Umgang mit der Shell zu lernen ist also kein Selbstzweck. Außerdem ist eine sichere Nutzung der Shell Grundlage für alle weiteren Selbstlernmodule von DevToolbox.

Die Shell erleichtert wiederkehrende Aufgaben besonders dann, wenn viele Dateien, große Datenmengen oder wiederholte Abläufe im Spiel sind: etwa beim konsistenten Umbenennen ganzer Dateisammlungen, beim automatisierten Aufbereiten von Log-Dateien, beim Zusammenführen oder Konvertieren von Dokumenten oder beim reproduzierbaren Herunterladen und Verarbeiten von Datenquellen.

Bei der Nutzung einer GUI werden diese Aufgaben durch eine Reihe von Klicks in verschiedenen Fenstern und Menüs erreicht. Daraus ergeben sich einige Nachteile, die vor allem dann deutlich werden, wenn solche Aufgaben häufig durchgeführt werden müssen. Dem gegenüber stehen die Vorteile der Shell-Nutzung:

Effizienz & Wiederverwendbarkeit:

Wiederkehrende Abläufe können in einer kurzen und eindeutig beschreibbaren Form festgehalten und bei Bedarf automatisiert ausgeführt werden. Dadurch entfällt die Notwendigkeit, dieselben Schritte jedes Mal manuell zu wiederholen, was nicht nur Zeit spart, sondern auch die Fehleranfälligkeit gegenüber dem händischen Vorgehen deutlich reduziert. Die Wiederverwendbarkeit solcher Abläufe erstreckt sich auf alle Systeme mit Shell-Unterstützung. Dadurch stellt die Shell im Kontext verschiedener Systeme eine Art kleinsten gemeinsamen Nenner dar.

Reproduzierbarkeit & Nachvollziehbarkeit:

Arbeitsabläufe können so dokumentiert werden, dass sie später (oder von anderen) in gleicher Weise wiederholt werden können. Das ist zentral für Fehlersuche, wissenschaftliches Arbeiten sowie die Arbeit im Team.

Flexibilität & Kombinierbarkeit:

Shell-Werkzeuge lassen sich so miteinander verbinden, dass aus einfachen Bausteinen komplexe Verarbeitungsketten entstehen. Damit wird die Shell zu einer Schaltzentrale für Werkzeuge und Prozesse.

Grafische Oberflächen sind hervorragend, um intuitiv und ohne großes Vorwissen mit einem System zu interagieren. Sobald Abläufe jedoch häufiger auftreten, dokumentiert, geteilt oder auf andere Systeme übertragen werden sollen, werden Klickfolgen schnell unübersichtlich. Die Shell ergänzt die GUI daher nicht als Gegenteil, sondern als leistungsfähige Alternative für skalierbare und nachvollziehbare Arbeitsweisen.

Sie kennen nun die Vorteile der Shell-Nutzung und erkennen die große Relevanz für die Informatik. Vielleicht fragen Sie sich an dieser Stelle aber immer noch, was eine Shell überhaupt sein soll. Diese Frage beantworten wir im nächsten Abschnitt.

Was ist eine Shell und was nicht?

Die Shell ist eine textbasierte Schnittstelle zum Betriebssystem. Dabei ist die Shell kein einzelnes, fest definiertes Programm, sondern eine ganze Klasse von Programmen mit ähnlicher Funktion. Es existieren unterschiedliche Shells, etwa bash, zsh (heute häufig Standard unter macOS) oder fish (mit Fokus auf Bedienkomfort). Sie unterscheiden sich unter anderem in Voreinstellungen, Komfortfunktionen und teils auch in Details der Skript-Sprache. Die Grundidee bleibt jedoch gleich: Eine Shell stellt eine textbasierte Schnittstelle bereit, um Programme zu starten und Arbeitsabläufe zu automatisieren.

Die Programme, die sie startet rufen den Betriebssystemkern meistens Kernel genannt auf. Der Kernel verwaltet Hardware und stellt grundlegende Dienste bereit. Der Zugriff geschieht über definierte Schnittstellen.

Die nachfolgende Abbildung (entnommen aus dem Buch Linux kurz & gut: Die wichtigen Befehle, zu finden unter dem Reiter Lernressourcen Text) veranschaulicht die Verortung der Shell im Gesamtkontext. 

Der Zugriff auf die Shell erfolgt über ein Terminal (bzw. Terminalemulator), denn die Shell selbst hat keine eigene Schnittstelle für Nutzer:innen. Auch Programme mit GUI nutzen im Hintergrund die Shell. Sie können dies testen, indem Sie ein solches Programm statt bspw. über das Startmenü zu öffnen, über ein Terminal aufrufen. Dort werden Sie die Ausgabe der Software sehen, die als Seiteneffekt der regulären Nutzung über die GUI entsteht.

Wenn Sie ein Terminal starten sehen Sie eine Eingabeaufforderung auch Prompt oder Befehlszeile genannt. Die Form bzw. der Inhalt unterscheidet sich von System zu System, häufig sieht der Prompt folgendermaßen aus:

<benutzer:in>@<rechner>:~$

Hinter dem $-Zeichen erfolgt nun die Eingabe. Das ist der Startpunkt für die Shell-Nutzung.

Einordnung: Linux, Open Source und die Rolle der Shell

In diesem Kurs nutzen wir das Betriebssystem Linux. Machen Sie sich keine Sorge, sollten Sie Windows oder macOS nutzen. Wir stellen in diesem Kurs zunächst alle Lernressourcen so bereit, dass Sie sie von jedem Betriebssystem aus per Browser nutzen können. Linux ist der de facto Standard für Server-, Cloud- und Hochleistungsrechner und stellt damit die Grundlage für das gesamte Internet dar. Diese Dominanz ist nicht zuletzt darauf zurückzuführen, dass es sich bei Linux um Open Source Software handelt, also Software, die quelloffen und kostenfrei zur Verfügung steht. Die Shell spielt darin eine zentrale Rolle, weil sie als stabile, ressourcenschonende und gut automatisierbare Schnittstelle funktioniert und über verschiedene Systeme hinweg gleich funktioniert und wiederverwendbar ist.

Verantwortungsvoller Umgang

Die Shell ist ein äußerst mächtiges Werkzeug, das jedoch auch destruktiv eingesetzt werden kann. Mit einem einzigen Befehl (sofern Sie über die entsprechenden Berechtigungen im Betriebssystem verfügen) ist es möglich, das gesamte System unwiderruflich zu löschen, ohne dass eine Nachfrage zur Bestätigung erfolgt. Darüber hinaus sollten Sie stets datenschutzrechtliche Aspekte berücksichtigen. Insbesondere bei administrativem Zugriff auf Server, auf denen auch Daten anderer Nutzer:innen gespeichert sind, ist ein verantwortungsvoller Umgang mit diesen Daten unerlässlich.

Fazit

Sie kennen nun die wichtigsten Gründe, warum die Shell in vielen informatischen Kontexten eine zentrale Rolle spielt, wie sie im System verortet ist und haben erste grundlegende Informationen zur Nutzung erhalten.
